# 账号与团队

当前开发版本已重建存储结构，旧账号、项目、上传记录和文件数据已按开发阶段要求清空；根目录的 Sketch 样本保留。没有旧数据迁移，也没有全局管理员绕过团队权限。

## 日常流程

1. `/register` 注册独立账号，用户名 2–50 字符（英文、数字、点、横线、下划线），密码 6–200 字符。用户名忽略大小写且全局唯一。
2. 注册成功进入工作台，自动打开最近使用且仍有权限的团队；只有一个团队时直接进入。没有团队时引导创建工作空间，也可以稍后打开邀请链接。注册不自动创建团队。
3. 团队创建者成为拥有者。一个账号可以拥有或加入多个团队。
4. 团队拥有者和管理员创建项目，并在团队成员页面生成邀请链接。当前为链接邀请，不会发送邮件。
5. 受邀者打开 `/invite/:token`，注册或登录后返回同一个邀请页面，主动接受邀请。
6. 普通成员加入后需由管理者分配项目权限。团队成员不会自动获得所有项目的访问权。

## 权限

| 角色 | 权限 |
| --- | --- |
| 团队拥有者 | 所有团队管理权限；可邀请管理员、调整管理员/成员角色；拥有全部团队项目的管理权 |
| 团队管理员 | 创建项目、邀请普通成员、撤销邀请、移除普通成员、管理全部团队项目；不能调整拥有者或其他管理员 |
| 团队成员 | 查看团队成员；仅访问被分配的项目；可以另建自己的团队 |
| 项目可上传 | 查看、上传新稿、重新处理、设为当前稿 |
| 项目可查看 | 查看文档与资源，不能上传或调整当前稿 |

拥有者不能被移除或降级。拥有者转让、账号找回和 SSO 尚未实现。项目角色不会提升团队角色。只能把本团队成员加入项目。

移除团队成员时同步清除该团队下全部显式项目授权，并撤销其创建的未使用邀请。重新邀请回来不会恢复旧项目权限。单独移除项目授权不影响该账号的团队身份。

## 邀请

- 32 字节随机令牌，数据库仅保存 SHA-256；原始链接只在生成时展示，之后可撤销并重新生成。
- 固定有效期 7 天，单个链接供一人使用，固定加入角色。管理员只能生成普通成员邀请。
- 已加入团队的账号接受新邀请不会被升级或降级，需要拥有者明确调整角色。
- 同一接受者重复操作可安全重试，但被移除后不能凭已使用邀请重新加入。
- 已使用、过期、撤销或不存在的链接有明确状态；其他账号不能再次使用已经接受的邀请。
- 邀请链接不会记录到正常请求日志，页面设置 `Referrer-Policy: no-referrer`。请仍只向预期成员分享链接。

## 地址与存储

`/login`、`/register`、`/teams`、`/teams/:teamId`（团队主页）、`/teams/:teamId/workspace`（工作台）、`/teams/:teamId/members`。项目及稿件继续使用 `/projects/:projectId/documents/:documentId/revisions/:revisionId`，页面与画板由查询参数定位。

`users` 保存账号，`team_members` 保存团队成员关系，`projects.team_id` 明确项目所属团队，`members` 保存显式项目授权。原文件及解析产物仍由既有对象存储和任务处理层管理。

团队、项目、设计及上传记录的公开 ID 为 12 位随机字符串，使用 Node.js `randomBytes` 生成，并检查已有 ID 及映射避免冲突。新记录直接使用短 ID。已有 UUID 记录通过 `public_ids` 表获得稳定短 ID，内部主键和关联不改写，不删除文件或历史记录；API 输入先解析映射，再执行原有权限校验。旧链接仍可访问，浏览器会转换为短链接。邀请令牌、文件内容哈希以及 Sketch 内部页面/图层 ID 保持原样。备份仍需包含整个 SQLite 与数据目录。

登录、注册、邀请、团队和项目权限均由后端验证。开放部署后当前注册允许任何能访问应用的人创建账号；团队与项目仍隔离。此版本定位可信局域网试用，未提供账号治理、配额和生产级审计。

接口测试覆盖注册边界与重复用户名、多团队隔离、邀请接受与重复/过期/撤销、角色边界、成员移除后权限失效及不可通过旧邀请恢复权限。浏览器流程在隔离测试数据目录验证，正式数据目录留空供用户注册。

## 工作台体验

日常入口围绕项目与设计文件。侧边栏直接展示可展开的团队 → 项目层级，上方显示「团队」小标题和创建团队加号；团队旁的更多菜单提供成员邀请、新建项目和创建团队入口。默认展开当前团队，其他团队可独立展开；点击团队名称进入独立团队主页，展示项目卡片与成员入口；工作台继续展示设计文件。项目选中态只保留背景色，不显示左侧高亮条。文件卡片可以直接打开固定稿件，更多菜单提供上传记录、上传新稿及复制链接。上传和新建项目通过弹窗完成；空项目支持拖入 Sketch 并进入上传流程。上传弹窗可以收起，当前标签页内任务继续；页面刷新仍需重新选择文件续传。界面色彩在 `src/theme.css` 统一，使用深灰文字、中灰辅助信息和紫色重点状态，不修改画布中的设计稿颜色。

搜索、网格/列表切换可用于设计文件。最近打开只在当前浏览器保存文档 ID 和时间，按账号隔离，展示时仍由后端项目权限筛选，不会跨设备同步。文件卡片当前使用统一格式封面，并非 Sketch 画板缩略图。图标使用 Lucide React。

直接打开稿件链接时，首帧显示查看器加载骨架与处理状态；失败时提供重试和返回工作台，不显示本地文件欢迎首页。

## 删除与快捷操作

团队与项目支持右键或更多按钮打开操作菜单，设计卡片也支持右键及更多菜单。团队仅拥有者可删除；项目由团队拥有者或管理员删除；设计由项目可上传成员或团队管理者删除。删除前展示范围与不可撤销的确认弹窗，后端独立验证权限。删除团队级联移除项目、文档、稿件、上传记录、邀请与成员关系；删除项目、设计按相应范围处理，数据库事务保证失败时全部回滚。正在上传、校验或解析的内容会阻止删除，完成后再操作。

原文件、图片对象与解析产物可能被多个设计复用，当前删除只清理业务记录，共用资源继续保留；尚未提供存储垃圾回收或回收站。旧链接删除后返回不存在或无权访问。

应用显示名称为 GeekDesign，现有仓库、环境变量和本地偏好键保持兼容。查看器顶部提供「返回项目」及「切换设计」，切换器可选择有权限的项目及其中的设计。


## 名称编辑与设计移动

团队拥有者和管理员可在团队的更多操作中重命名团队、项目；具有上传能力的成员可在设计的更多操作或右键菜单中重命名设计、移动设计。

设计可移动到同一团队内有上传权限的其他项目，保留设计 ID、全部版本、当前稿和预览，无需重新上传。正在上传或解析的设计需完成后再移动。版本链接仍按原版本定位，有访问权限的用户打开旧链接后会自动更新到新项目地址。移动后使用目标项目现有的访问规则。


## 团队字体库

团队页的「字体库」支持搜索、上传、预览和删除字体。拥有者和管理员可维护字体，普通成员可查看和预览。支持 TTF、OTF、WOFF、WOFF2，单个文件不超过 20 MB；自动读取名称、字重、样式，不支持 TTC 字体集合。相同内容重复上传会复用；同一个 PostScript 名称的不同文件需先删除旧版本，避免字体匹配歧义。

团队设计详情按原稿中的字体名自动加载所需字体，不需要在每个项目重复配置。本地文件查看仍使用本机或手动加载的字体。团队字体不用于现有总览缩略图的服务端生成；远景预览仍为简化排版。

字体元数据保存在 SQLite，文件位于 `data/fonts/`，请随整个数据目录一起备份。删除字体后，新打开的设计不再加载该字体；已打开页面刷新后生效。删除元数据不立即清理共用的字体文件。
